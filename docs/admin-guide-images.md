# Admin Guide — Tiered Upgrade Images & Guide Images

The Admin **Manage Creatures** → **Images** tab lets admins generate tiered
(Tier 1–4) concept images for each creature, review them, and promote approved
images to **guides** that the card generator uses as visual/style reference.
Generating or approving an image **never creates a card** — guides only inform
future card art.

## 1. Generate tiered images

1. Expand a creature → **Images** tab → **Generate Image(s)**.
2. Pick a **Tier** (1–4). Each tier has built-in guidance (Base → Legendary).
3. (Optional) Type a **detailed prompt**. If you leave it blank, the server
   auto-builds a complete tier-appropriate prompt from the tier guidance + the
   creature's description + its Unique Attack summary, and stores it with
   `promptAutoGenerated = true`. The final prompt is always stored on the
   image record, so you can see exactly what was sent.
4. Pick **Count** (1–5) and a **Style** preset. A live **Final prompt preview**
   shows the exact text that will be sent to the image provider.
5. **Generate**. Records start as `pending`; the provider fills in the URL.
   Per-image failures are kept as `pending` with an error message so you can see
   which ones failed.

Tier guidance defaults:

- **Tier 1 (Base):** faithful creature, clean silhouette, simple background.
- **Tier 2 (Enhanced):** light armor/elemental accents, slight dynamic pose.
- **Tier 3 (Major):** elaborate armor, elemental effects, glowing runes, cinematic lighting.
- **Tier 4 (Legendary):** iconic, ornate, particle effects, halo/glow, dramatic lighting.

The final prompt template (admin instructions omitted when blank):

> Creature: {baseName}. Tier: {tier}. Theme/Style: {style}. [Admin instructions: {adminPrompt}.] Tier instructions: {tierGuidance} Visual requirements: full-body, 4:5 aspect ratio, transparent/neutral background, high-res, clear silhouette, no watermarks. Palette: {palette}. Unique attack: {summary}. Anatomy: {description}. Deliverable: 1 finished concept image suitable as a card art guide. [close-up for tier≥3]

## 2. Review: Approve as Guide / Reject

Each tile shows its tier, status, and (once approved) a **GUIDE** badge.

- **Approve as Guide** → status `approved`, `isGuide = true`. The image is now
  available to the card generator for this creature + tier. Opens a confirm
  modal with an optional note (audit-logged).
- **Reject** → status `rejected`, `isGuide = false`. Kept in history, never used.
  Rejecting a previous default also clears the creature's reference image.

## 3. Set Default for Tier

On an approved guide, **Default · T{n}** sets it as the default guide for that
creature + tier (`isDefaultForTier = true`) and mirrors its URL onto
`Creature.referenceImageUrl`, which the card-art generator reads as the anatomy
reference. At most one guide is the default per tier.

## 4. Use in Card Generator

On any approved guide, **Use in Card Generator** opens the AI Generate page with
the guide preselected (`?guide=<id>&creature=<baseName>&tier=<n>`). The guide is
passed to `generateCardArt` as `guideImageId`, which the server validates is an
approved guide belonging to a creature with the same base name — unapproved or
mismatched images can never be used (returns 409/400). A `used_in_card_generator`
audit event is logged. (Admin-only: only admins can force a specific creature,
so the guide actually matches the generated card.)

## 5. Manual import

**Import Image** lets you upload a file (via UploadPublicFile) or paste a URL,
pick the target tier, and attach an optional prompt note. Imported images start
`pending` and go through the same Approve-as-Guide flow.

## Audit history

The **Activity** feed under the gallery logs every action with the acting admin,
timestamp, and note: `generate_requested`, `generate_completed`, `generate_failed`,
`image_uploaded`, `approve_guide`, `reject_image`, `set_default_tier`,
`used_in_card_generator`.

## Backend functions

- `generateCreatureImages` — `{ creatureId, tier, prompt?, count, style }` →
  auto-builds the prompt when `prompt` is empty, stores `promptAutoGenerated`,
  creates `pending` records, fills URLs. Returns `{ images, generated, failed, promptAutoGenerated }`.
- `uploadCreatureImage` — `{ creatureId, url, tier?, prompt? }`.
- `approveCreatureImage` — `{ imageId, setDefault?, note? }` → approve as guide;
  `setDefault` also makes it the default for its tier. 409 if still generating.
- `rejectCreatureImage` — `{ imageId, note? }`.
- `setDefaultCreatureImage` — `{ imageId }` → default guide for its tier.
  409 unless the image is an approved guide.
- `getGuideImages` — `{ creatureId, tier? }` → approved `isGuide` images only.
- `generateCardArt` — `{ baseName, type, isHybrid, guideImageId? }` → validates
  the guide server-side before using it.

## Risk summary

- **Provider cost:** each generate call hits the restricted GenerateImage
  integration once per image. Mitigation: count capped at 5; tier guidance keeps
  prompts consistent so fewer retries are needed.
- **Prompt length:** over-long prompts are truncated to `MAX_PROMPT_LENGTH`
  (2000 chars) with a logged warning and a `prompt auto-truncated` note on the
  record.
- **Partial failure:** per-image failures are surfaced (`generated`/`failed`
  counts in the response; failed records keep `errorMessage`).
- **Concurrency:** approving while a generation is pending returns 409 (no URL
  yet). Setting a default for a tier clears the previous default for that tier
  atomically.
- **Guide misuse:** `generateCardArt` re-validates the guide's
  `status === 'approved' && isGuide` and that it belongs to a creature with the
  same base name — client-supplied guide ids cannot bypass this.
